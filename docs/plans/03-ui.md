# Plan 03 — UI: Download Buttons Everywhere, Edge Cases, Usability

Goal: fix the reported bug (no download button in the media-viewer full view) and generally make the button available wherever media is on screen, with modern feedback UX. Depends only on the `TweetCache` contract (00-overview).

## 1. The reported bug, diagnosed

`check_media_tweets()` scans **only the primary column**:

```js
// src/js/main_react.user.js:4669
.find( 'div[data-testid="primaryColumn"] article[role="article"]' )
```

The photo/media viewer (URL `/<user>/status/<id>/photo/<n>`, also `/i/…` immersive video view) renders inside the separate overlay root `div#layers`, *not* inside `primaryColumn`. So the injection pass never sees it. On wide screens the modal shows a tweet-detail sidebar (which is also inside `#layers` → still no button); on narrow screens / "full view" there is no sidebar at all — exactly the user's report: you must close the viewer and use the post view to download.

## 2. Injection surfaces (v1 scope)

| Surface | Location | Anchor for button | Tweet-ID source |
|---|---|---|---|
| Timeline / post-detail tweet | `main` column `article[data-testid="tweet"]` | action row `div[role="group"]` (reply/RT/like/…): insert before the share/overflow item | tweet permalink `a[href*="/status/"] time` parent (existing approach, keep) |
| **Media viewer (photo)** | `#layers`, URL `…/status/<id>/photo/<n>` | the viewer's own action bar `div[role="group"]` under the image; fallback: floating button top-right of the image stage | **URL** — `location.pathname.match(/\/status\/(\d+)\/photo\/(\d+)/)`; `<n>` selects the *current* photo |
| **Media viewer (video/immersive)** | `#layers` / `/i/status/…` video overlay | same pattern | URL `/status/(\d+)/video/(\d+)` or `/i/status/(\d+)` |
| Quoted tweet's media | inside `div[role="link"]` block of the quoting tweet | no button (matches current behavior — the quoted tweet gets its own button on its own page); *do* make sure quote media is not mis-attributed to the outer tweet (legacy code filters this via href matching, keep that logic) |

Media-viewer behavior detail: the viewer button downloads the **currently displayed item** by default; long-press/dropdown or Alt-free secondary action offers "all media in this post". Keyboard navigation (←/→) changes `<n>` in the URL — re-read the URL at click time, don't cache the index at injection time.

## 3. Watching the DOM

- Keep the single debounced `MutationObserver` on `document.body` doing batched scans (the legacy "scan everything, dedupe via class marker" approach at `main_react.user.js:4728` is actually the right resilience call for X's virtualized lists — do not switch to per-node processing).
- Add: scan `#layers` in the same pass; also listen for SPA URL changes (wrap `history.pushState`/`replaceState` + `popstate` — the URL is the source of truth for the viewer) to trigger an immediate scan instead of waiting for mutations.
- Dedupe marker: keep a `data-twmd` attribute instead of legacy class names.
- All selectors live in `dom-selectors.js` (plan 01) with the shape `{ candidates: [sel1, sel2], validate(el) }` — X renames `data-testid`s rarely but reshuffles wrappers often; candidate lists + a validation predicate beat single brittle chains. **Verify every selector above against the live x.com DOM at implementation time; the table is a starting map, not gospel.**

## 4. Button design & states

Replace the legacy text button (`メディア`/`Media` text in a gradient-styled `<button class="btn">`, styled to 2019 Twitter) with an icon button that matches X's current action row:

- Inline SVG download icon, sized/colored via `currentColor` inside X's own action-item hover halo markup; tooltip via `title` (keep it simple).
- States: idle → in-progress (spinner or animated stroke; button disabled, cursor progress — keep legacy's re-entrancy guard) → success flash (✓, ~1.5 s) → idle; error state (! icon + toast).
- Feedback: replace every `alert()` (`main_react.user.js:4240,4323,4396`…) with a small toast (bottom center, matches X dark/light theme). Night-mode detection: current `body[data-nightmode]` hack is replaced by reading X's theme from `<html style="color-scheme…">`/background color, still centralized in one helper.
- Enablement from cache: buttons render immediately; if the tweet isn't in `TweetCache` yet and has video, the click falls back per plan 02 §5 (photos work from DOM regardless). Optionally subscribe to `TweetCache.onUpdate` to upgrade the button's capability hint.
- Keep: Alt+Click (⌥ on Mac) = open-in-tabs instead of download, and the `OPEN_MEDIA_LINK_BY_DEFAULT` option that inverts it.

## 5. Edge cases checklist (test manually against live site)

- [ ] Photo modal, 1 of N photos; arrow-key navigation updates target.
- [ ] Photo modal opened directly by URL (cold navigation → cache initially empty → DOM/URL fallback works).
- [ ] Immersive video viewer; GIF posts ("GIF" badge) — saved with `gif` prefix per filename convention.
- [ ] Sensitive-media interstitial (media hidden behind "Show") — button should appear only after reveal, or work via cache regardless; decide and document.
- [ ] Retweets (media belongs to original author — filename uses original author, matching legacy behavior), quotes (outer button must not grab inner media).
- [ ] Long threads / virtualized scroll: buttons appear on recycled DOM nodes (the batch-scan handles this; verify no duplicates).
- [ ] Mixed-media posts (photos + video), 4-photo grids, alt-text present/absent.
- [ ] Narrow viewport (the exact reported scenario) and logged-out view (X heavily gates logged-out browsing; extension should degrade silently).
- [ ] Light/dim/lights-out themes.

## 6. Bulk-download dialog (defer heavy redesign)

Keep the existing dialog's functionality (range, limit, media-type checkboxes, dry-run, log pane, ZIP button) but: port markup out of jQuery, restyle minimally for current X, move strings to `_locales`. The timeline-header 「メディア↓」 link injection point (`check_timeline_headers`) needs re-anchoring to the current profile-header DOM — same `dom-selectors.js` treatment. Functional changes to bulk flow are plan 02 §6's scope, not here.

## Acceptance criteria

- Download button visible and functional in the photo modal full view, video viewer, and every timeline surface listed in §2 — including the exact repro from the bug report (media view full screen without opening post detail).
- Zero `alert()` calls remain; all feedback via button state + toasts.
- All selectors in one file; each has at least one live-DOM verification note (date checked).
